# 试玩协议（5–10 人）

目的：完成 M4 的验收条款「5–10 人试玩；多种构筑可用；死亡原因清楚」，并拿到可执行的调参数据。

## 1. 准备工作

```bash
npm ci
npm run build
npm run preview -- --port 4177
```

打开 `http://127.0.0.1:4177/`（不要用 `?arena=1`，那会跳过训练须知）。

- 每台设备用**无痕窗口**或先清一次 `localStorage`，保证能看到首启训练须知。
- 建议至少覆盖：桌面键鼠 3 人、手机 2 人（其中 1 人用横屏）。

## 2. 每位试玩者做 2 局

第 1 局：**不提示**，观察他是否能自己搞懂移动、闪避、清房拿规则。
第 2 局：告诉他「9 种组合 × 3 条突变」，让他有意识地做一次构筑选择。

每局结束的结算页会自动记录：用时、击杀、清空步数、最终组合、突变、累计战绩（最近 20 局）。

## 3. 观察清单（按优先级）

1. **是否理解闪避**：会不会在红色预警出现前就交闪避？会不会说「我明明躲了还是被打」？
2. **是否理解规则来源**：清房后的三选一，能不能说出「这条规则来自哪个敌人」？
3. **死亡归因**：被击败时能不能说出「是被什么打死的」？（冲锋 / 扇形弹幕 / 火焰地面 / 自爆 / BOSS 封印）
4. **构筑手感**：哪一套组合让他觉得「明显变强」？哪一套觉得没用？
5. **节奏**：第几房开始感到压力？有没有「想快点结束」的房？
6. **精英与 BOSS**：第一次遇到精英/ BOSS 时是否看懂机制（双冲锋 / 三连雷击 / 扇形弹幕 / 封印预警）。
7. **手机**：摇杆遮挡、闪避按钮误触、横屏视野、文字大小。

## 4. 收集数据

每位试玩者结束 2 局后，在浏览器控制台执行：

```js
copy(JSON.stringify(JSON.parse(localStorage.getItem('rulethief.runs.v1') ?? '[]'), null, 2))
```

粘贴到一个文本文件，命名 `player-N.json`，和口头反馈一起提交。

如果控制台不可用，直接截图结算页（含「累计 N 局 / 最快 / 最常构筑」那一行）。

## 5. 已知需要重点验证的假设

这些是自动化测试覆盖不到、必须靠人判断的：

- **贯穿是否偏弱**：木桩基准里贯穿 26–99 dps，低于散射/弹射的爆裂组合（127–138）。但贯穿依赖敌人排队，真实战斗可能更差。
- **冰霜是否只值控制**：它的 DPS 最低（26–73），减速上限 50%。如果玩家普遍不选它，需要给冰霜补一点即时伤害。
- **弹射 + 爆裂是否过强**：已把跳跃触发的命中效果伤害降到 0.6 倍，但仍是最强组合。
- **精英墙的位置**：自动试玩在第一个精英（第 9 步）从 140 HP 掉到 22 HP。真人是否也觉得这里是断崖？
- **封印是否可读**：第三阶段脚下 1.15 秒预警，玩家是否能反应过来并走出圈。

## 6. 反馈模板

```text
试玩者：#N  设备：桌面 / 手机(竖/横)
第 1 局：到达第 X 步，用时 mm:ss，组合 ____，死亡原因 ____
第 2 局：到达第 X 步，用时 mm:ss，组合 ____，死亡原因 ____
最顺手的组合：
最没用的组合：
看不懂的地方：
手机问题（如有）：
一句话感受：
```

## 7. 回收后的处理

1. 把各人的 `player-N.json` 汇总，统计：平均到达步数、通关率、最常用组合、死亡原因分布。
2. 对照第 5 节的假设逐条判断是否成立。
3. 只做**有证据**的调整（例如「3 人都没选冰霜」→ 给冰霜补即时伤害），并把数值变化同步到 `tuning.test.ts` 与 `docs/M4_TUNING.md`。
