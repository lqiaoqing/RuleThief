# 试玩协议（M6–M9，5 人）

目的：完成蓝图的真人验收条款——至少 5 名真实玩家走完三世界路线，记录构筑选择、死亡原因与再玩意愿；同时回收可执行的调参与手感数据。

## 1. 准备工作

```bash
npm ci
npm run build
npm run preview -- --port 4177
```

打开 `http://127.0.0.1:4177/`（不要用 `?arena=1`，那会跳过训练须知）。

常用入口：

- 完整路线：`http://127.0.0.1:4177/`
- 单练旧 BOSS：`?arena=1&boss=1`
- 指定构筑：`?arena=1&build=spread,burn,3,3`（弹道,命中,弹道等级,命中等级）
- 指定种子：`?seed=demo`
- 从第二/第三世界开始（需先在法则图鉴解锁）：`?start=1` / `?start=2`
- 异变难度：`?mutator=1` … `?mutator=5`
- 每日挑战：`?daily=1`

每台设备用**无痕窗口**或先清一次 `localStorage`，保证能看到首启训练须知与默认解锁状态。

建议覆盖：桌面键鼠 3 人、手机 2 人（其中 1 人横屏）。桌面与手机各至少 2 人走完第一世界，至少 2 人走完三世界或到达第三世界。

## 2. 每位试玩者做什么

**第 1 局（必做）**：不提示，完整路线或直到死亡。记录到达世界/步数、用时、构筑、遗物、升阶、死亡原因。

**第 2 局（可选，时间允许）**：告诉玩家「9 种主组合 × 第三规则槽 × 3 条突变 × 升阶 × 遗物 × 高阶强化」，让其有意识地做一次高阶构筑；或指定一套组合做 10 分钟对比。

单局目标 25–35 分钟；如果玩家在第 1 世界后选择收工，也算一次有效的阶段结算样本，请记录。

## 3. 观察清单（按优先级）

1. **世界差异**：进入第二世界前 2 分钟，能否说出环境机制（放电地板/传送带）与第一世界的不同？第三世界的虚空裂隙与逆律是否可读？
2. **章节奖励**：第一世界 BOSS 后的三选一，是否感觉「明显变强」，还是只是加数值？
3. **升阶与遗物**：能否说出自己拿到的升阶/遗物效果？有没有「质变」时刻？
4. **后半程成长**：第二世界是否仍有构筑选择，还是全部满级只能拿加血？
5. **死亡归因**：能否说出「被什么打死的」？（冲锋 / 弹幕 / 火焰 / 自爆 / 放电 / 虚空 / BOSS 封印）
6. **节奏**：第几房开始感到压力？25–35 分钟是否过长或过短？
7. **世界起点**：如果解锁了 W2/W3 起点，继承构筑是否让开局更顺，还是直接劝退？
8. **异变/每日**：异变 I–V 的难度变化是否可感知？每日种子是否有再打一次的动力？
9. **手机**：摇杆遮挡、闪避误触、横屏视野、文字大小、发热/掉帧。

## 4. 收集数据

每局结束的结算页点击 **「导出试玩数据」**，会下载 `rulethief-playtest-<时间戳>.json`，包含：

- 最近 20 局：章节深度、用时、击杀、组合、突变、遗物、升阶、异变、每日标记、完整构筑、承伤来源；
- 局外存档：碎片、解锁、成就、最高异变、起点解锁、每日最佳；
- 浏览器 UA 与当前 URL。

把文件重命名为 `player-N.json`，和口头反馈一起提交。

若按钮不可用，在控制台执行：

```js
copy(JSON.stringify({
  runs: JSON.parse(localStorage.getItem('rulethief.runs.v1') ?? '[]'),
  meta: JSON.parse(localStorage.getItem('rulethief.meta.v1') ?? 'null')
}, null, 2))
```

## 5. 重点验证假设

- **单局时长**：三章结构模型 25–35 分钟；真人是否落在区间？第二/第三世界各 9–12 分钟是否成立？
- **章节奖励强度**：升阶/遗物是否足够「可感知」，还是不如直接加等级？
- **构筑强弱**：贯穿+冰霜仍是最低 DPS 基准（26–73）；弹射+爆裂仍最强（114）。真人是否也这样感知？
- **精英墙**：第 9 步精英、第二世界护盾舱、第三世界先知竞技场是否断崖？
- **世界起点**：W2/W3 继承 Lv.2/Lv.3 双规则 + 1/2 遗物，是否过强或过弱？
- **异变**：I–V 的 HP/速度/额外精英/环境频率变化是否可感知但不劝退？
- **可读性**：放电/虚空预警、逆律封印、失序核心的安全区变化是否看得懂？

## 7. 已回收的样本

见 [PLAYTEST_RESULTS.md](./PLAYTEST_RESULTS.md)。目前只有 M5 阶段的 1 局桌面样本（08:30 通关，散射+燃烧，敌弹承伤 60%，且该承伤只覆盖 BOSS 房）。M6–M9 的三世界、升阶、遗物、世界起点、异变与每日挑战尚无真人样本。

## 8. 回收后的处理

1. 汇总 `player-N.json`：平均到达世界/步数、通关率、单局时长、最常用组合、遗物/升阶选择率、死亡原因分布、异变选择。
2. 对照第 5 节逐条判断；只做**有证据**的调整（例如 3 人都没选冰霜 → 补即时伤害）。
3. 数值变化同步到 `tuning.test.ts`、`docs/STATUS.md` 与验收矩阵；每次调整后重跑 `npm test`、`npm run smoke`、`npm run fullrun`。
