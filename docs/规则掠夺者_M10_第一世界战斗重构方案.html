01 / CORE DIAGNOSIS

真正的问题，是战斗循环没有反馈玩家的成长

一次真实试玩已足以确认“不好玩”；根因需要对照代码与可重复的对照试玩验证。
PAIN 01

强者反而更无聊

怪物会被秒杀，但刷怪间隔不随清怪速度改变，玩家只能等系统按节拍一只只生成。

PAIN 02

关卡名称不同，打法相同

第 5–12 步以相近的怪物数量、固定两种敌人组合和类似刷怪速率构成，缺少战术冲突。

PAIN 03

成长、空间都缺少变化

大多数规则升级更偏数值，800×800 小场地难以形成真正的追击、绕行、撤退和掩体利用。

↳

改造方向：不以“增加血量、增加房间、增加技能”为第一反应。先让玩家的强度能够影响推进速度，再让每场战斗有不同的压力，再提升规则成长和地图空间的变化。

02 / ROOT CAUSE

代码证据：等待时间是由刷怪器锁死的

把用户的主观感受转化为能被验证的机制问题。

当前规则

每次生成 1 个敌人；未达到配额且场上数量未超上限时，按固定 spawnInterval 调用传送门。传送门还有 550ms 特效延迟。

一个 22 只怪、2.3 秒间隔的普通房间，首只到最后一只的理论投放跨度约 48.3 秒。即使全程秒杀，等待的下限仍在。

对应源码入口

src/game/rooms.ts 定义每房 quota / maxAlive / spawnInterval / mix。

src/game/M0Scene.ts 的 updateSpawns() 逐只生成，spawnPortal() 延迟 550ms 入场。

src/game/theme.ts 使用 ARENA = 800。

03 / WAVE DIRECTOR

M10.0：从逐只刷怪，改为响应战况的连续怪潮

这一项优先级最高。先在第 7 房做可玩对照实验，再决定是否推广。

旧模式：固定配额、均匀投放

一只怪出现 → 玩家秒杀 → 等待约 2–3 秒 → 再来一只。玩家更强，仍必须等待最后一只被生成。

玩家成长无法缩短无聊时间。

新模式：成组投放、动态推进

每波 4–9 只，按战况提前或重叠投放；清怪越快，下一波越早；玩家可主动提前召唤，换取更高风险和额外奖励。

战斗节奏会随着强度与操作改变。

互动模拟 · 同样 22 只怪，等待机制改变多少？

拖动“清理一波需要的时间”，比较固定逐只投放与 4 波怪潮的理论过程。

说明性模型 · 非实测

玩家清怪能力

平均清理每波所需3.0 秒
试试 1.5 秒（强构筑）与 8 秒（较弱构筑）。新模式中弱构筑会遇到短暂怪潮重叠，但会严格限制同屏敌人数量。
固定刷怪跨度48.3s

假设：旧模式每 2.3 秒投放 1 只，共 22 只；新模式共 4 波（5/6/5/6 只），间隔最多 3 秒；若清完则 0.7 秒后提前推进。旧模式显示的是出生时间跨度，新模式显示的是含最后一波清理在内的粗略完成时间；二者仅用于理解机制，不可直接作为实际通关时间预测。

怪潮调度的 MVP 契约

RULE 01

先批量，后节奏

将敌人分为波次，初期每波 2–3 只，中段 4–6 只，后期 6–9 只。不要把新增总怪数当成游戏设计本身。

RULE 02

清空即提前

上一波全部清空后，下一波通常在 0.7–1 秒内到来；仍须保留出生预警、防止连续贴脸秒杀。

RULE 03

过载但有边界

强玩家可选择提前下一波；重叠怪潮必须受同屏容量、投射物数与特效预算保护。

不要这样改：把 spawnInterval 全部改成 0.1 秒、把 maxAlive 全改为 100、把怪物 HP 同比例提高。这只会把等待问题换成性能问题与数值膨胀。
04 / CHAPTER REDESIGN

M10.1：第一世界重排为 7 场战斗 + 1 场 BOSS

短而密，不依靠重复房间堆时长。随机事件作为房间间短暂插曲，不额外制造“刷怪关”。

01 / 基础构筑

觉醒之厅

约 20–30 秒 · 引导玩家了解技能选择

  • 快速获得第一条弹道规则。
  • 简单低密度怪潮，为下一场做铺垫。
  • 确保玩家不会以“等待刷新”作为第一印象。
体验关键词：快速建立能力
战术构想 · 示意非游戏截图
✓

新的章节验收：八场战斗至少包含四种不同的战斗意图：高速清怪、远程站位、精英规避、环境危险。不能只是八张相似配置表。

05 / BUILD EVOLUTION

M10.3：从“数值升级”到“规则共鸣”

不要再给玩家更多同质卡片。给一次真正改变战斗方式的里程碑奖励。

现有玩家体验

规则 Lv.1 → Lv.2 → Lv.3 往往表现为数量、持续时间、伤害等变化。中途已经成型的构筑，后续选择缺乏惊喜。

原先
规则升级 → 数值更大 → 自动秒怪 → 等待更多

改造目标

第 5 场给予一次「规则共鸣」：让已有的两规则组合产生一个新的操作反馈，后续能继续通过奖励强化它。

改造后
规则搭配 → 战术形态变化 → 新怪潮提供挑战 → 爽感反馈
组合案例规则共鸣（拟定）改变了什么需要守护的实现约束
弹射 + 爆裂累计多目标有效命中后释放一次雷暴冲击鼓励寻找高密度敌群冲击不再触发新的冲击；共享触发预算
散射 + 燃烧近距离命中足够目标时形成短暂火焰领域鼓励主动贴近和绕位限制领域数量、持续时间和伤害触发
贯穿 + 冰霜穿透多目标后在轨迹上留下冰霜通道通过站位制造控场路线减速叠加有上限；不无限复制效果
通用闪避后的下一轮攻击获得短时强化提高移动与闪避价值不允许无代价永久叠加

06 / SPACE & MOVEMENT

M10.2：扩大地图之前，先创造走位的价值

先制作一个可滚动测试房。不能直接把所有 ARENA 常量改大。

① 跟随镜头

可见区域小于完整地图；对屏外威胁提供方向提示，避免无法预判的伤害。

② 掩体和路径

至少 2 个可挡弹幕的固定障碍，并能让近战与远程敌人形成不同的绕位压力。

③ 环境危险

一种缓慢扩张的危险区，迫使玩家离开安全点；清晰预警，保留躲避空间。

工程约束：当前 ARENA = 800 影响地图、出生位置、敌人边界、玩家限制、BOSS 行为和弹体范围。先抽出地图边界与摄像机参数，保持旧房间兼容；只让一个测试房使用新地图尺寸。

09 / CODEX HANDOFF

交给 Codex 的首轮任务指令

一次只做 M10.0；保持旧玩法和 M6–M9 流程可回归。
M10.0 / FIRST IMPLEMENTATION CONTRACT
项目：RuleThief / Phaser + TypeScript + Vite
任务：M10.0「怪潮节奏重构」最小可玩切片。

背景：用户在第一世界第 7–8 关明显感到疲劳。当前逐只刷怪（多数房间 22 怪、2.3–3 秒间隔、800×800 战场）导致玩家秒怪后长时间等待。

本次范围：
1. 新增独立、可单元测试的 WaveDirector 纯逻辑模块；状态明确、输入输出明确，不预建庞大通用框架。
2. 仅选择第一世界一个测试房（优先现有第 7 房）使用怪潮；其余房间行为保持不变。
3. 采用分组生成：初始波次 4–6 只；上一波清空后在约 0.7–1 秒内推进；玩家可主动提前召唤下一波；严格限制同时存在敌人和特效。
4. 对生成、取消、房间清理、玩家死亡、暂停/恢复、BOSS 胜负状态添加边界测试；严禁残留延迟生成跨房污染。
5. 增加客观指标：无敌可打时间占比、最后一波生成时间、清房时间、峰值敌人数、异常/控制台错误。
6. 提供旧版与怪潮版的对照测试入口，可用固定 seed；保留可回退开关。

硬约束：
- 不重做全部 13 关、不扩大地图、不新增怪物、不改第三槽及遗物功能。
- 不简单缩短所有 spawnInterval；不要把所有怪物血量抬高来阻止秒杀。
- 不在 5k+ 行 M0Scene.ts 中继续累积大段新规则；调度核心应在独立模块。
- 优先最小 diff，分阶段提交；修改前后执行单测、类型检查、已有冒烟与全流程测试。
- 对 UI / 刷怪 / 弹体效果设置明确容量上限，保留玩家可辨认的出生预警。

交付物：
A. 最小实现与独立测试；
B. 第 7 房可玩对照；
C. 指标记录（含对照数据）；
D. 变更文件清单、风险、回退办法；
E. 未实测的手感不能自称达标。

完成标准：在同怪同房条件下，强构筑不再持续等待逐只刷怪；且旧世界流程无回归。
