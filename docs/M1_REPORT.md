## 3. 架构

- `src/game/rules.ts`：纯逻辑层。规则定义、等级描述、`getRuleOffers`（先升级、再空槽、最后随机，且永不重复给同一条）、`applyRuleOffer`、`TriggerBudget`、`selectChainTargets`、`getSpreadAngles`、`mergeBurn` / `mergeFrost`、`getBuildCombo`、`buildLevelSum`。
- `src/ui/altar.ts`：只负责把 `RuleOffer[]` 渲染成三张卡（含等级 pip、升级/替换提示、组合预览、键盘序号）。
- `src/ui/hud.ts`：`setBuild(build, acquired)` 统一刷新双槽、手机 dock、等级计数、组合横幅、图鉴状态。
- `src/game/M0Scene.ts`：
  - `fireAttack` 按弹道 profile 分派：散射（多弹扇形）/ 贯穿（定向多命中）/ 弹射或基础（homing）。
  - `updateBolts` → `handleBoltHit` → `applyImpact`。命中效果只在真实弹体命中时触发。
  - `applyBuildState` 是唯一入口：切换弹道会清空在飞弹体，切换命中会清空全部敌人身上的燃烧/冰霜，避免"旧规则残留"。
  - `applyTrainingRule` 处理训练碎片：空槽装备、同规则升级、冲突时改为回复 8 生命（绝不自动替换）。

### 防递归与预算

一次 `fireAttack` 创建**一个** `TriggerBudget(3)`，所有由这次攻击派生的命中（贯穿多目标、散射多弹、弹射跳跃）共享它。`resolveChain` 与 `applyImpact` 每次结算前 `tryConsume()`；预算耗尽后弹体继续飞行但不产生新的命中效果。`applyDamage` 的 `'dot'` / `'blast'` 分支不会再触发规则，因此燃烧跳伤与爆裂范围伤害不会形成回路。

## 4. 规则祭坛

- 触发：每 15 击杀（15/30/45…）自动开启；暂停菜单「规则祭坛 · M1 RULE LAB」可随时打开演练。
- 打开时暂停场景与计时（实测冻结：`elapsed` 在等待 400ms 后无变化）。
- 三选一，卡片显示：槽位、名称、装备/升级/替换标签、等级 pip、升级后效果、当前槽位状态、替换警告、组合预览。
- 键盘 `1/2/3` 选择，`Esc` / 「暂不掠夺」跳过；跳过不改变构筑。
- 全部规则满级时祭坛不开启，改为回复 10 生命。

## 5. 验收

### 单元测试（22/22）

`npm test` → `src/game/rules.test.ts` 19 项 + `src/game/theme.test.ts` 3 项。

覆盖：9 个组合名、单槽部分名称、等级数值递增、空构筑补满两槽、始终提供可升级项、升级保留另一槽、替换重置 Lv.1、满级不再提供升级、组合预览、等级总和、预算上限 3、燃烧/冰霜刷新规则与减速上限、弹射目标唯一性与射程、散射角度对称。

关键项：空构筑 → 训练碎片装备 → 祭坛暂停与计时冻结 → 升级保留另一槽 → 替换重置 Lv.1 并保留对立槽 → 9 组合名称逐一比对 → 单槽部分名称 → 满级无升级项 → 15 击杀自动开祭坛 → 暂停菜单规则实验室 → 结算显示最终组合与等级 6/6 → 重开完全重置 → 手机祭坛三卡可点选且不溢出 → 无 console/page error。

## 7. 已知偏差与边界

1. **训练碎片映射与设计文档不一致**：设计文档中铁刺甲虫掉「贯穿」，当前为覆盖两个槽位，甲虫掉「爆裂」、雷蝠掉「弹射」。M3 补齐 6 种敌人时改回。
2. **祭坛是 M1 的临时获取方式**：正式流程应在每场房间战后给奖励（M2）。每 15 击杀触发只是为了在没有房间流程时也能完整体验构筑。
3. 规则满级后没有额外转化（如碎片换血/换伤害），目前只是回血。
4. 只有 2 种敌人，因此 9 种组合的平衡差异缺少对空验证；真人试玩仍未进行。
5. 尚未做存档 / 跨局解锁。
