# M5 移动端、音频、性能与部署

日期：2026-10-26
范围：双端输入与响应式、音频解锁与静音、性能复核、静态构建与部署校验。

## 1. 移动端

- 左侧虚拟摇杆（Pointer Events + 指针捕获），右侧闪避按钮，支持多点触控同时移动与闪避。
- 布局断点：≥980px 侧栏 HUD；<980px 切换为顶部状态条 + 底部构筑 dock；横屏（高度 <520px）使用 `min(width - 360, height - 16)` 收缩竞技场。
- 安全区：HUD 与底部控件的定位使用 `env(safe-area-inset-*)`。
- 覆盖层（房间预览 / 奖励 / 路线 / 事件）在 390×844 与 844×390 下均可完整显示，移动端单列堆叠、可滚动。
- 已自动验证：摇杆移动、闪避按钮、房间进入、奖励点选、路线选择；**真机触控与手感仍未验收**。

## 2. 音频

- 全部音效为运行时 WebAudio 合成（无外部音频文件）：射击、命中、爆炸、冲刺、受伤、死亡、规则获得、胜利/失败，另有环境 drone。
- 首次指针交互解锁 AudioContext；失焦/切后台自动 suspend，回来 resume。
- 右上角按钮静音，状态写入 localStorage。
- 已自动验证：`audio.contextState === 'running'`、静音按钮 aria 状态切换。

## 3. 性能

| 场景 | 帧率（headed Chrome，硬件 WebGL） |
| --- | --- |
| 房间 1，19 敌人 + 5 处火焰地面 | 59.3fps |
| BOSS 第三阶段，11 发扇形弹幕 + 召唤物 | 60.3fps |
| 移动端模拟（离线渲染 + 移动视口） | 功能通过；帧率不代表真机 |
| 压力测试：40 敌人 + 46 发敌方弹幕 | **59.0fps**（最低 59） |

压力测试命令：`BASE_URL=http://127.0.0.1:4177 node scripts/stress.mjs`，脚本会一次性生成 40 个混合敌人并采样 10 次。

- **峰值上限**：同屏伤害数字上限 48、命中火花上限 64，超出直接跳过，避免极端连击时的对象暴涨；40 敌压测中实际峰值为伤害数字 12、火花 5。
- 未做完整对象池：敌人与弹体仍为即时创建销毁；当前峰值（40 敌人 / 46 敌弹）下未见掉帧。
- 已知风险：低端机与长时间运行（>10 分钟）的 GC 抖动未验证。

## 4. 静态构建与部署

```bash
npm ci
npm test          # 75 项单测
npm run build     # tsc --noEmit + vite build
npm run preview -- --port 4177
BASE_URL=http://127.0.0.1:4177 npm run smoke
BASE_URL=http://127.0.0.1:4177 npm run verify
```

- `npm run verify` 会校验：JS/CSS bundle、8 个精灵、地砖、菜单图、构建体积（<8MB）以及 HTML 中没有 dev server 引用。
- 当前产物：`dist` 1.85MB；`public/assets` 约 460KB。
- 试玩记录保存在浏览器 localStorage（`rulethief.runs.v1`，最多 20 局），不涉及后端。
- 部署方式：把 `dist` 整个目录上传到任意静态托管（Nginx / OSS / GitHub Pages / Netlify）。项目没有后端、没有环境变量、没有运行时配置。
- 注意：`index.html` 使用相对路径 `./assets/...`，因此可以部署在子目录下（例如 `https://example.com/rule-thief/`）。

## 6. 部署后检查清单

1. 打开首页，确认菜单背景图与字体加载正常。
2. 进入游戏，确认第一次点击后出现音效（AudioContext 解锁）。
3. 手机竖屏：摇杆可拖动、闪避按钮可点、底部构筑条不遮挡摇杆。
4. 清空第一房，确认奖励三选一可点、路线选择出现。
5. 打完 BOSS，确认结算显示 9/9 与最终组合。
6. 刷新页面后能重新开始（当前没有存档，属预期）。
